## Schema

### `cases` table

```sql
CREATE TABLE cases (
    run_id TEXT PRIMARY KEY,
    service_order_id TEXT,
    employee_name TEXT,
    case_type TEXT,
    status TEXT NOT NULL,
    priority TEXT,
    flagged BOOLEAN NOT NULL DEFAULT 0,
    last_changed_at TEXT NOT NULL,
    created_at TEXT NOT NULL,
    state_snapshot TEXT NOT NULL
);
CREATE INDEX idx_status ON cases(status);
CREATE INDEX idx_last_changed ON cases(last_changed_at DESC);
CREATE INDEX idx_flagged ON cases(flagged) WHERE flagged = 1;
```

- **`run_id`:** Thread ID from `State['run_id']`
- **`service_order_id`:** From `State['service_order_id']`
- **`employee_name`:** Derived via `backend.employee_name(state['service_order'])`
- **`case_type`:** Heuristic from `service_order` structure (verify extraction logic in HLD)
- **`status`:** One of `{'running', 'needs_input', 'needs_review', 'done', 'rejected', 'failed'}` (matches `State['status']`)
- **`priority`:** One of `{'high', 'medium', 'low'}` (from `State['priority']`)
- **`flagged`:** Boolean (from `State['flagged']`)
- **`last_changed_at`:** ISO 8601 timestamp (updated on every state write)
- **`created_at`:** ISO 8601 timestamp (set once at case creation)
- **`state_snapshot`:** JSON blob of full `State` dict (for resume/reconstruction)

### `case_flags` table

```sql
CREATE TABLE case_flags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id TEXT NOT NULL,
    flag_id TEXT NOT NULL,
    flag_type TEXT NOT NULL,
    resolved BOOLEAN NOT NULL DEFAULT 0,
    FOREIGN KEY (run_id) REFERENCES cases(run_id) ON DELETE CASCADE
);
CREATE INDEX idx_case_flags_run_type ON case_flags(run_id, flag_type, resolved);
```

- **`run_id`:** Foreign key to `cases.run_id`
- **`flag_id`:** From `Flag['flag_id']` in `State['flags']`
- **`flag_type`:** From `Flag['type']` (e.g. `netPayMismatch`, `missingData`)
- **`resolved`:** From `Flag['resolved']` (filters show only `resolved=0`)

## API Contracts

### `GET /cases`

**Query parameters:**

- `status` (optional): Comma-separated list of statuses (e.g. `running,needs_review`)
- `priority` (optional): Comma-separated list of priorities (e.g. `high,medium`)
- `flagged` (optional): `true` or `false` (boolean filter)
- `flag_type` (optional): String (e.g. `netPayMismatch`); filters cases with at least one unresolved flag of that type
- `case_type` (optional): Comma-separated list of case types
- `sort` (optional): `last_changed` (default, descending) or `wait_time` (ascending; only valid when `status=needs_review`)
- `page` (optional): Integer (default `1`)
- `page_size` (optional): Integer (default `25`, max `100`)

**Response (200 OK):**

```json
{
  "cases": [
    {
      "run_id": "abc123",
      "service_order_id": "SO-1001",
      "employee_name": "Jane Doe",
      "case_type": "Offboarding",
      "status": "needs_review",
      "priority": "high",
      "flagged": true,
      "last_changed_at": "2025-01-15T14:30:00Z"
    }
  ],
  "total": 42,
  "page": 1,
  "page_size": 25
}
```

**Errors:**

- `400 Bad Request` — Invalid filter value (e.g. unknown status):
  ```json
  {"error": "Invalid status: invalid_status. Allowed: ['running', 'needs_input', 'needs_review', 'done', 'rejected', 'failed']"}
  ```
- `400 Bad Request` — `page_size > 100`:
  ```json
  {"error": "page_size must be between 1 and 100"}
  ```

---

### `GET /cases/counts`

**Query parameters:**

- `by_status` (optional): `true` or `false` (default `true`)
- `flagged` (optional): `true` or `false` (default `true`)

**Response (200 OK):**

```json
{
  "by_status": {
    "running": 5,
    "needs_input": 2,
    "needs_review": 8,
    "done": 120,
    "rejected": 3,
    "failed": 1
  },
  "flagged_waiting": 3
}
```

- **`by_status`:** Count per status (all statuses included, even if count is 0)
- **`flagged_waiting`:** Count of cases where `status='needs_review' AND flagged=true`

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| **SQLite write contention under high load** | API writes block on DB lock; slow response times | Use `aiosqlite` with `timeout` parameter (default 5s); monitor contention; defer to Postgres if measurable bottleneck arises |
| **Checkpointer and SQLite state divergence** | List view shows stale data; counts incorrect | Persistence hook runs **synchronously** in checkpoint write path; write failure fails the run and logs error |
| **Large `state_snapshot` blobs slow queries** | `/cases` response time degrades as case count grows | Index only metadata columns (`status`, `last_changed_at`, `flagged`); `state_snapshot` retrieved only by `/runs/{thread_id}` (single-case endpoint) |
| **Migration failure on startup crashes server** | Service unavailable until manual intervention | Migration runner logs errors and exits cleanly; rollback procedure documented in `migrations/README.md` |
| **Filter injection (malicious `flag_type`)** | Data leak or query failure | All filter values validated at FastAPI layer; parameterized SQL queries prevent injection |
| **Wait time calculation ambiguity** | AC10 "sort by wait time" unverifiable without `waiting_since` field | Open question: assume `last_changed_at` when status became `needs_review` for now; may require schema amendment (`waiting_since` column) after clarification |
| **Case type extraction heuristic undefined** | AC7 filter by `case_type` may be inaccurate | Open question: verify whether `service_order['caseType']` is verbatim or requires mapping; placeholder `None` for missing logic |

## Verification Strategy

Each AC maps to a test case (details in LLD `Tests` section):

- **AC1–AC4:** Query `/cases` with no filters; verify all statuses present, correct pagination, default sort.
- **AC5–AC9:** Query with each filter type; verify correct filtering and combinations.
- **AC10:** Query with `flag_type=netPayMismatch`; verify only unresolved flags of that type appear (join `case_flags` where `resolved=0`).
- **AC11:** Query with `status=needs_review&sort=wait_time`; verify ascending order (requires `waiting_since` clarification).
- **AC12:** Query `/cases/counts`; verify counts match case list totals.
- **AC13:** Restart server; query `/cases`; verify cases created before restart still appear with correct status.
- **AC14:** Query with invalid filter value; verify `400 Bad Request` with allowed values message.
- **AC15:** POST `/runs/{thread_id}/resume`; verify existing single-case operations unchanged.

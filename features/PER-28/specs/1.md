# Technical Specification: FastAPI SSE Integration with Agent Service

**Ticket:** #1  
**Component:** fastapi-backend  
**Type:** Integration  
**Status:** Draft

---

## Overview

Implement FastAPI integration with an external agent service providing synchronous immediate responses and asynchronous status updates via Server-Sent Events (SSE). FastAPI acts as a pure pass-through: it forwards the agent's immediate reply and streams the agent's events exactly as received, with no timer logic, no status creation, and no delay. The agent owns all timing logic, including any delays or status transitions.

## Component Breakdown

### 1. Query Router (`routers/query.py`)

**Dependencies:**
- `AgentClient` (agent_client.py)
- `RunRegistry` (run_registry.py)
- `QueryRequest`, `ImmediateResponse` (query_models.py)
- `sse-starlette.EventSourceResponse`

**Endpoints:**

```python
@router.post("/query", response_model=ImmediateResponse)
async def submit_query(request: QueryRequest) -> ImmediateResponse:
    """
    AC1: Return agent's immediate reply without delay.
    - Generate run_id (UUID4)
    - Call agent_client.initiate_query()
    - Register run in RunRegistry (ID mapping only)
    - Return {status, run_id} synchronously
    - Raise HTTPException(503) if agent unreachable
    """

@router.get("/query/{run_id}/stream")
async def stream_status(run_id: str) -> EventSourceResponse:
    """
    AC2-AC5: Stream SSE events forwarded from agent.
    - Validate run_id exists in RunRegistry
    - Subscribe to agent event stream
    - Forward events exactly as received (pure pass-through):
      - in_progress → SSE event: in_progress
      - completed → SSE event: completed
      - failed → SSE event: failed
    - Close stream after terminal event (completed or failed)
    - Clean up registry mapping in finally block
    - NO timer logic, NO event creation, NO delay
    """
```

### 2. Agent Client (`services/agent_client.py`)

**Dependencies:**
- `httpx.AsyncClient`
- `config.AGENT_BASE_URL`, `config.AGENT_TIMEOUT`

**Interface:**

```python
class AgentClient:
    async def initiate_query(self, query_data: dict) -> dict:
        """
        Call agent POST /agent/query.
        Returns: {"status": "ok"|"rejected", "agent_run_id": str}
        Raises: httpx.HTTPError if agent unreachable/timeout
        Timeout: 3 seconds (immediate reply expected)
        """

    async def subscribe_to_run(self, agent_run_id: str) -> AsyncIterator[dict]:
        """
        AC4: No polling - subscribe to agent SSE stream.
        Yields: {"event": "in_progress"|"completed"|"failed", "data": dict}
        Timeout: 5 minutes total (long-running run timeout)
        Pure pass-through: forwards agent events exactly as received.
        """
```

**ASSUMPTION:** Agent service streams events in SSE format. Adjust if agent uses WebSocket/gRPC.

### 3. Run Registry (`services/run_registry.py`)

**Dependencies:**
- `typing` (Optional)

**Interface:**

```python
class RunRegistry:
    def __init__(self):
        self._runs: dict[str, str] = {}  # run_id -> agent_run_id

    def register_run(self, run_id: str, agent_run_id: str) -> None:
        """Create new run ID mapping."""

    def get_agent_run_id(self, run_id: str) -> str:
        """Retrieve agent run ID for SSE routing. Raises KeyError if not found."""

    def remove_run(self, run_id: str) -> None:
        """Remove run ID mapping, preventing memory leak."""
```

**Note:** In-memory only, stores only ID mappings (no timestamps, no status). No persistence required per current scope.

## Pure Pass-Through Architecture

**CRITICAL:** FastAPI does **not** create, decide, or delay run status. The agent owns all timing logic, including any delays (such as the 5-second delay mentioned in the original ticket, which will be implemented in a later agent-side ticket). FastAPI is a pure pass-through:

1. **POST /query:** Forwards the agent's immediate reply (Ok or rejected) synchronously, registers the ID mapping for SSE routing.
2. **GET /query/{run_id}/stream:** Subscribes to the agent's event stream and forwards events exactly as received. No `in_progress`/`completed`/`failed` generation, no timer logic, no delay.

**Location:** `routers/query.py::stream_status()`

```python
# Pseudocode
async def stream_status(run_id, agent_client, registry):
    # Validate run_id exists
    agent_run_id = registry.get_agent_run_id(run_id)
    
    async def event_generator():
        try:
            # Subscribe to agent event stream (single connection)
            async for agent_event in agent_client.subscribe_to_run(agent_run_id):
                # Forward event exactly as received (pure pass-through)
                event_type = agent_event["event"]
                event_data = agent_event["data"]
                
                # Serialize to SSE format
                sse_message = f"event: {event_type}\ndata: {json.dumps(event_data)}\n\n"
                yield sse_message
                
                # Close after terminal event
                if event_type in ("completed", "failed"):
                    break
        finally:
            # Cleanup registry mapping (prevent memory leak)
            registry.remove_run(run_id)
    
    return EventSourceResponse(event_generator())
```

**Key Points:**
- Zero timer logic
- Zero `in_progress`/`completed`/`failed` generation
- Only forwards what the agent already sent
- Agent owns all timing and status decisions

## Risks & Mitigations

### Risk 1: Run ID Collision
**Mitigation:** Use `uuid.uuid4()` (collision probability negligible).

### Risk 2: Agent Service Unavailable
**Mitigation:**
- 3-second timeout on `initiate_query()`
- Return `503 Service Unavailable` if agent unreachable
- Log error for monitoring

### Risk 3: Agent Event Stream Disconnection
**Mitigation:**
- 5-minute total timeout on `subscribe_to_run()`
- Send `failed` event with "timeout" error if no terminal event received
- Close SSE stream, cleanup run state

### Risk 4: Memory Leak (Uncleaned Run Registry)
**Mitigation:**
- `remove_run(run_id)` called immediately after terminal SSE event sent in `finally` block
- Registry stores only ID mappings (no timestamps), so no stale state accumulates
- Monitor registry size for anomalies

### Risk 5: Client SSE Disconnection
**Mitigation:**
- Detect disconnect via `EventSourceResponse` built-in mechanism
- Cancel agent subscription (stop iterating `subscribe_to_run()`)
- Do NOT cancel agent run (it completes independently)
- Cleanup run state after disconnect

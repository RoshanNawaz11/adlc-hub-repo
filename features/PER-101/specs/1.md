## Schema / API Contracts

### Idempotency Store Interface

```python
from typing import Protocol, Literal

class IdempotencyStore(Protocol):
    async def claim(self, key: str, thread_id: str) -> Literal["claimed", "running", "completed"]:
        """
        Atomically claim the run key.
        
        Returns:
            "claimed": This worker now owns the run. Proceed to execute.
            "running": Another worker owns the run. Skip execution.
            "completed": The run already finished. Skip execution.
        
        Raises:
            IdempotencyUnavailable: Backend is unreachable and claim cannot be guaranteed.
        """
        ...

    async def complete(self, key: str, thread_id: str) -> None:
        """
        Mark the run as completed. Idempotent (safe to call multiple times).
        Logs error if backend is unreachable, does not raise.
        """
        ...

    async def release(self, key: str, thread_id: str) -> None:
        """
        Release the claim (run paused, failed, or cancelled).
        Logs error if backend is unreachable, does not raise.
        """
        ...
```

### Redis Key-Value Schema

**Key format:** `run-idempotency:{idempotency_key}`  
where `{idempotency_key}` is the output of `idempotency_key(task)` (unchanged function in `src/agents/runtime/idempotency.py`).

**Value schema (JSON string):**

```json
{
  "state": "running" | "completed",
  "thread_id": "<uuid>",
  "claimed_at": "<iso8601 timestamp>",
  "completed_at": "<iso8601 timestamp>"
}
```

**Note:** `completed_at` is only present when `state` is `"completed"`.

**TTLs:**
- **Running state:** `IDEMPOTENCY_CLAIM_TTL_SECONDS` (default 3600, set via `EXPIRE` on `SET NX`)
- **Completed state:** `IDEMPOTENCY_COMPLETED_TTL_SECONDS` (default 604800, set via `EXPIRE` on completion `SET`)

**Redis operations:**
- **Claim:** `SET run-idempotency:{key} <json_value> NX EX {claim_ttl}` → returns 1 (claimed) or 0 (exists)
  - If 0, `GET run-idempotency:{key}` → parse JSON and return `state` field as `"running"` or `"completed"`
- **Complete:** `SET run-idempotency:{key} <json_value> EX {completed_ttl}` (unconditional SET, overwrites running)
- **Release:** `DEL run-idempotency:{key}`

## Risks

### Risk 1: Redis Single Point of Failure
**Impact:** If Redis is down, all workers fail fast on `claim` and cannot start runs.  
**Mitigation:** Redis is already a required dependency (arq queue). The system's availability already depends on Redis. Fail-fast on `claim` prevents silent corruption. Operational monitoring should alert on Redis downtime.  
**Residual:** Low. The failure mode is explicit (`IdempotencyUnavailable` logged and job marked failed).

### Risk 2: Claim TTL Too Short Causes Duplicate Execution
**Impact:** If `IDEMPOTENCY_CLAIM_TTL_SECONDS < typical_job_duration`, a long-running job's claim will expire mid-run, allowing a second worker to claim and start a duplicate execution.  
**Mitigation:** Default TTL (3600s) matches `ORDER_JOB_TIMEOUT`. Document the relationship in `.env.example`. Recommend adding a startup validation warning if `IDEMPOTENCY_CLAIM_TTL_SECONDS < ORDER_JOB_TIMEOUT`.  
**Residual:** Medium. Operational misconfiguration could cause duplicates. Manual verification (PR description) will test the default case.

### Risk 3: `complete` Failure Leaves Stale `running` Entry
**Impact:** If Redis is unreachable at completion time, the entry remains `running` until the claim TTL expires. Retries within the TTL window will skip (return `"running"`), even though the run actually finished.  
**Mitigation:** Log the failure. The claim TTL bounds the unavailability window (default 1 hour). The trade-off favors preserving the run result over blocking retries—non-idempotent actions (`create_ticket`, `notify_on_call`) have already executed.  
**Residual:** Medium. Acceptable because re-running on `complete` failure would duplicate non-idempotent actions.

### Risk 4: Worker Crash Between `claim` and First Status Write
**Impact:** Worker A claims and crashes before writing `running` status to `order-run:{thread_id}`. The job appears stuck. Worker B cannot claim (entry is `running`). Claim TTL eventually expires, allowing retry.  
**Mitigation:** Existing `ORDER_JOB_TIMEOUT` already bounds this. The status write and claim are not atomic, but the claim TTL provides eventual recovery.  
**Residual:** Low. This is an existing failure mode; the idempotency layer does not worsen it.

### Risk 5: Concurrent Completion Race
**Impact:** Worker A's claim expires while the graph is still running. Worker B claims and starts a second execution. Worker A finishes and calls `complete` while Worker B is running. The last writer wins (Worker A or B), and both executions' `thread_id` values appear in separate `order-run:{thread_id}` status keys.  
**Mitigation:** The default claim TTL (3600s) is tuned to typical job duration. If jobs routinely exceed 1 hour, operators must increase both `IDEMPOTENCY_CLAIM_TTL_SECONDS` and `ORDER_JOB_TIMEOUT`.  
**Residual:** Medium. Rare in practice (requires a job to run longer than the TTL and Redis to be available). Observable via duplicate status keys.

## Implementation Notes

### `src/agents/runtime/idempotency.py` Structure

```python
import asyncio
import json
import logging
from datetime import datetime, timezone
from typing import Literal, Protocol
from redis.asyncio import Redis
from redis.exceptions import ConnectionError as RedisConnectionError
import os

logger = logging.getLogger(__name__)

class IdempotencyUnavailable(Exception):
    """Raised when the idempotency backend is unreachable during claim."""
    pass

class IdempotencyStore(Protocol):
    async def claim(self, key: str, thread_id: str) -> Literal["claimed", "running", "completed"]:
        ...
    async def complete(self, key: str, thread_id: str) -> None:
        ...
    async def release(self, key: str, thread_id: str) -> None:
        ...

class MemoryIdempotencyStore:
    def __init__(self):
        self._state: dict[str, dict] = {}
        self._lock = asyncio.Lock()
    
    async def claim(self, key: str, thread_id: str) -> Literal["claimed", "running", "completed"]:
        async with self._lock:
            if key not in self._state:
                self._state[key] = {
                    "state": "running",
                    "thread_id": thread_id,
                    "claimed_at": datetime.now(timezone.utc).isoformat()
                }
                return "claimed"
            return self._state[key]["state"]
    
    async def complete(self, key: str, thread_id: str) -> None:
        async with self._lock:
            self._state[key] = {
                "state": "completed",
                "thread_id": thread_id,
                "claimed_at": self._state.get(key, {}).get("claimed_at", datetime.now(timezone.utc).isoformat()),
                "completed_at": datetime.now(timezone.utc).isoformat()
            }
    
    async def release(self, key: str, thread_id: str) -> None:
        async with self._lock:
            self._state.pop(key, None)

class RedisIdempotencyStore:
    def __init__(self, redis_url: str, claim_ttl: int, completed_ttl: int):
        self._redis = Redis.from_url(redis_url, decode_responses=True)
        self._claim_ttl = claim_ttl
        self._completed_ttl = completed_ttl
    
    def _redis_key(self, key: str) -> str:
        return f"run-idempotency:{key}"
    
    async def claim(self, key: str, thread_id: str) -> Literal["claimed", "running", "completed"]:
        redis_key = self._redis_key(key)
        value = json.dumps({
            "state": "running",
            "thread_id": thread_id,
            "claimed_at": datetime.now(timezone.utc).isoformat()
        })
        try:
            result = await self._redis.set(redis_key, value, nx=True, ex=self._claim_ttl)
            if result:
                return "claimed"
            # Key exists, read state
            existing = await self._redis.get(redis_key)
            if existing:
                data = json.loads(existing)
                return data["state"]
            # Race: key expired between SET NX and GET
            return "claimed"
        except RedisConnectionError as e:
            raise IdempotencyUnavailable(f"Cannot reach Redis: {e}")
    
    async def complete(self, key: str, thread_id: str) -> None:
        redis_key = self._redis_key(key)
        value = json.dumps({
            "state": "completed",
            "thread_id": thread_id,
            "claimed_at": datetime.now(timezone.utc).isoformat(),
            "completed_at": datetime.now(timezone.utc).isoformat()
        })
        try:
            await self._redis.set(redis_key, value, ex=self._completed_ttl)
        except RedisConnectionError as e:
            logger.error(f"Failed to mark run {key} complete: {e}")
    
    async def release(self, key: str, thread_id: str) -> None:
        redis_key = self._redis_key(key)
        try:
            await self._redis.delete(redis_key)
        except RedisConnectionError as e:
            logger.error(f"Failed to release claim {key}: {e}")

def get_idempotency_store() -> IdempotencyStore:
    backend = os.getenv("IDEMPOTENCY_BACKEND", "memory")
    if backend == "memory":
        return MemoryIdempotencyStore()
    elif backend == "redis":
        redis_url = os.getenv("REDIS_URL")
        if not redis_url:
            raise ValueError("REDIS_URL must be set when IDEMPOTENCY_BACKEND=redis")
        claim_ttl = int(os.getenv("IDEMPOTENCY_CLAIM_TTL_SECONDS", "3600"))
        completed_ttl = int(os.getenv("IDEMPOTENCY_COMPLETED_TTL_SECONDS", "604800"))
        return RedisIdempotencyStore(redis_url, claim_ttl, completed_ttl)
    else:
        raise ValueError(f"Unknown IDEMPOTENCY_BACKEND: {backend}")

def idempotency_key(task: str) -> str:
    """Generate idempotency key from task string. Unchanged from original."""
    return task  # or hash(task) if needed
```

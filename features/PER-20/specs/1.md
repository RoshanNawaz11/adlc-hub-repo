## Schema & API Contracts

### Agent Query API (FastAPI)

**Endpoint:** `POST /query`

**Request:**
```json
{
  "question": "string"
}
```

**Response (success):**
```json
{
  "answer": "string"
}
```

**Response (error):**
```json
{
  "error": "string"
}
```

**Behavior:**
- AC-1: Greeting/help → LLM direct answer, no MCP call.
- AC-2: Data question → LLM requests tool → FastMCP HTTP call → synthesized answer.
- AC-3: MCP unreachable or tool error → `{"error": "..."}`, process stays up.

---

### Health Endpoint (FastAPI)

**Endpoint:** `GET /health`

**Response:**
```json
{
  "status": "up",
  "mcp_reachable": true
}
```

**Behavior:**
- AC-4: Reports process up and MCP HTTP endpoint reachable without calling a tool.
- `mcp_reachable` uses lightweight connectivity check (e.g. HEAD request or cached probe).

---

### FastMCP HTTP Client → MCP Server

**Transport:** FastMCP HTTP (SSE) at `MCP_URL` (e.g. `http://127.0.0.1:8000/sse`)

**Tool calls:**
- `list_sales_order` → list of sales orders
- `list_employees` → list of employees  
- `get_sales_order_by_id(id: string)` → single sales order or `{"error": "..."}`
- `get_employee_by_id(id: string)` → single employee or `{"error": "..."}`

**ID normalization (preserved from existing logic):**
- Before HTTP call: `emp-001` → `EMP-001`

**Error contract:**
- Tool returns `{"error": "..."}` on failure.
- MCP server unreachable → HTTP client surfaces connection error.
- No stdio fallback (AC-3).

**Optional:**

## Risks

### R-1: MCP server unavailable

**Likelihood:** Medium  
**Impact:** High (agent cannot answer data questions)  
**Mitigation:**
- AC-3: clear error, no stdio fallback.
- AC-4: health endpoint surfaces MCP connectivity proactively.
- Operational monitoring on `/health` alerts when `mcp_reachable: false`.

### R-2: FastMCP HTTP transport mismatch

**Likelihood:** Low  
**Impact:** High (integration breaks)  
**Mitigation:**
- PER-18 defines MCP server FastMCP HTTP interface; this ticket consumes it.
- Verification item 2: integration test validates one tool call over HTTP.
- Assume SSE at `MCP_URL`; defer detailed transport contract to PER-18.

### R-3: ID normalization regression

**Likelihood:** Low  
**Impact:** Medium (wrong records returned)  
**Mitigation:**
- Exception criterion preserves existing normalization (`emp-001` → `EMP-001`).
- Verification item 2: test case includes ID normalization.

### R-4: LLM decision divergence

**Likelihood:** Low  
**Impact:** Medium (unexpected tool calls or direct answers)  
**Mitigation:**
- Constraint: LLM choice logic unchanged.
- Verification items 1 and 2: test direct answer and tool call paths.

### R-5: Async/sync HTTP client choice

**Likelihood:** Low  
**Impact:** Medium (performance or compatibility issues)  
**Mitigation:**
- FastAPI is async-native; prefer `httpx` async client for FastMCP HTTP.
- If existing LLM client is sync, use `asyncio.to_thread` or sync HTTP client (`requests`) with thread pool.
- Verify FastMCP client library compatibility with chosen HTTP client.
